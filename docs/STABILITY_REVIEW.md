## 性能

同一台隔离机器、同一份合成库（6622 句，词 JSON 约 1.1MB；2 万词频行，200 张到期卡，其中 30 张不在词频表）。这不是线上速度。

| 操作 | p50 | p95 |
| --- | --- | --- |
| 列考试 | 0.175 ms | 0.232 ms |
| 读一个子题的句子 | 1.164 ms | 1.461 ms |
| 到期词内连接（丢掉 30 张） | 0.369 ms | 0.546 ms |
| 到期词左连接（保留 200 张） | 0.360 ms | 0.524 ms |

左连接没有变慢，并且少丢词。这个数据量上没有证据支持改索引或重写查询，所以没有改表结构。

首页在缓存里的续学卷和接口返回的卷一致时，子题列表改成和首批请求一起发，少一次串行等待。用注入的 80ms 往返做模型：原先约 0.16 秒，对齐后约 0.08 秒。这只说明少了一次等待，不是 mystone.top 的测速。审计机直连 8000 的健康检查大约 0.44 秒，那是出口到主机的距离，不是 SQLite 查询时间，也没有当成优化成果。
